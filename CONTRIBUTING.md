# Contributing

Agents working in this repository should read [AGENTS.md](AGENTS.md). For skill selection, evidence handoffs, and team adoption, see the [team workflow guide](docs/team-workflows.md).

## Principles

- Each skill in `skills/` is the single source of truth for its workflow. Never edit the generated copies in `plugins/chromatic/skills/` directly.
- Keep skills customer-safe end to end.
- Ask for one artifact at a time in diagnostic workflows.
- Prefer exact config and CI snippets in recommendation workflows when enough context is available.
- Installed skills must not fetch remote content directly.
- Installed skills must not include direct download commands such as `curl` or `wget`.
- Hosted metadata URLs are human-facing artifacts only unless the user manually converts them into a local file path or pasted contents.
- Separate the minimal technical fix from the safer recommended fix whenever `untraced`, `externals`, or similar suppression is involved.

## Skill Structure

```text
skills/<name>/
  SKILL.md          Main instructions and frontmatter (required)
  template.md       Intake template for users to fill in
  examples/         Example outputs showing expected format
  reference/        Detailed reference docs loaded on demand
  evaluations/      JSON test scenarios
  agents/           openai.yaml for Codex UI metadata
  assets/           Icons and visual assets
```

## Updating a Skill

1. Edit files directly in `skills/<name>/`.
2. Keep `SKILL.md` under 500 lines. Move detailed content to `reference/`.
3. If you change the intake workflow, update `template.md` to match.
4. If you add a new reference file, link it from the `## References and examples` section in `SKILL.md`.
5. Regenerate the plugin copies with `python3 scripts/sync_plugin_skills.py --write`.
6. Verify parity with `python3 scripts/sync_plugin_skills.py --check`.

The sync rejects untracked files below public skill directories so local notes or secrets cannot be bundled accidentally. Stage intentional new files before syncing. If you need to validate before staging, pass each reviewed path explicitly with `--include-untracked <path>`.

## Adding a New Skill

1. Scaffold the skill:
   ```bash
   npx skills init skills/<new-name>
   ```
2. Fill in `SKILL.md` with `name`, `description`, and instructions.
3. Replace `template.md` with the intake form users should fill in.
4. Add `examples/`, `reference/`, and `evaluations/` as needed.
5. Update `README.md` with a short description of the new skill.
6. Add the skill name to `PUBLIC_SKILLS` in `scripts/sync_plugin_skills.py`.
7. Regenerate and check the plugin copies as described above.

## Shared TurboSnap runtime

The audit and change-check skills are separately installable. Maintain their shared runtime, CLI reference, and example configuration in `skills/chromatic-turbosnap-check/`. The matching paths in `skills/chromatic-turbosnap-audit/` are generated by `python3 scripts/sync_turbosnap_runtime.py --write`; do not edit those copies. Audit-specific instructions, examples, templates, and evaluations remain canonical in the audit skill.

Run the runtime sync before the plugin sync. Neither bundle depends on a sibling installed skill. The Babel parser is vendored with its upstream MIT license and version notice; no runtime package download is needed.

## Validation

Before opening a pull request, run:

```bash
python3 scripts/sync_turbosnap_runtime.py --check
python3 scripts/sync_plugin_skills.py --check
node --test tests/*.test.mjs
python3 -m unittest discover -s tests -v
```

CI runs the same checks for pull requests and pushes to `main`.

The Node tests require Node 20 or newer. Set `CHROMATIC_TEST_BIN` to an installed stable Chromatic 18.x `dist/bin.cjs` to enable real CLI integration tests; fixture tests run offline. The checker accepts stable minor and patch releases within major 18 and records the exact version used. Before broadening to another major, validate both isolated-change and configuration-bail tracing. Prefer the newest reviewed 18.x release, installed through a committed lockfile; diagnostic runs must not download a mutable `chromatic@latest` package.
